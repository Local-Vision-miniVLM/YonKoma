# YonKoma 設計思想・仕様

## プロダクトの芯

YonKoma は **漫画制作ツール** ではなく、**日記を「小回りの落ち」付き四コマに変換する儀式** を支援するツールである。

| やること | やらないこと（初期） |
|----------|----------------------|
| 日記からテーマ・起承転結・落ちを抜く | 汎用マンガエディタ全機能 |
| 同じキャラデザで4コマを揃える | 長編・多キャラ大作 |
| 超ラフ鉛筆風の統一画風 | 厚塗り・彩色アニメ塗り |
| ラフ下描きを構図の正本にする | プロ向け動画工場 |

## ユーザー体験の原則

1. **日記が入力の正本** — 長いプロンプトより、今日の出来事のテキストから始める。
2. **落ちは編集者が考える** — AI はギャグより「日常のズレ・自虐・余韻」を優先する。
3. **絵は1コマずつ** — 4コマ1枚より4画像。コスト・再生成・一貫性のトレードオフを取る。
4. **キャラシートが顔の正本** — 先に1枚作り、以降のコマは参照画像で揃える。
5. **ラフが構図の正本** — 手描きスケッチがあるときはポーズ・配置を尊重する。
6. **セリフは後付け** — 画像に文字を焼き込まず、UI で吹き出しを重ねる。

## 画風ロック（Style Lock）

生成プロンプトに共通で埋め込む制約:

- 超ラフな鉛筆スケッチ（ノートに30秒で描いた線）
- グラファイトの黒線、ごく薄い陰影、彩色なし
- トーン・ベタ塗り・デジタル塗り禁止
- キャラは記号的でシンプル（特徴3〜4個）
- 背景は最小限
- 吹き出し・タイトルは画像に描かない

## アーキテクチャ（v0.1）

```
[ブラウザ UI]
  ├ キャラ設定・ラフキャンバス
  ├ 日記入力・台本編集
  └ 四コマプレビュー（セリフ重ね）

[Next.js API Routes]
  ├ POST /api/script  → 台本 JSON（起承転結4コマ）
  └ POST /api/image   → キャラシート or コマ画像

[生成バックエンド]（現状: Gemini API）
  ├ テキスト: gemini-2.5-flash 等
  └ 画像: gemini-2.5-flash-image 等（参照画像対応）
```

### データモデル（概要）

- `Character` — 名前、見た目、性格、識別ポイント、`sheetDataUrl`
- `Script` — title, theme, punchline, panels[4]
- `Panel` — role (ki/sho/ten/ketsu), visual, dialogue, caption

キーはブラウザ `localStorage`（`yonkoma-db`）。サーバーに API キーを永続保存しない。

## 生成パイプライン

### 台本

入力: 日記テキスト + Character  
出力: JSON（4コマ、各コマの visual / dialogue / caption）  
方針: 派手なギャグより日常の小さなズレで落とす。

### 画像

**キャラシート** (`mode: sheet`)

- 任意: ユーザーのキャララフを参照
- 正面・斜め・表情3つを1枚に

**コマ** (`mode: panel`)

- 参照1: キャラシート（見た目の正本）
- 参照2: コマラフ（構図の正本、任意）
- 1コマのみ、4つ並べない

## バックエンド方針（検討中）

| モード | 用途 | 備考 |
|--------|------|------|
| `gemini`（現行） | 品質・一貫性優先 | 画像APIは無料枠外・従量課金 |
| `ollama`（将来） | 台本のみローカル無料 | 32GB RAM で現実的 |
| `local-sd`（将来） | GTX 1650 Ti 等で試作・反復 | 4GB VRAM 制約あり |
| ハイブリッド | 台本ローカル + 絵クラウド | コストと品質のバランス |

ローカル全面移行は **プロダクト価値が低い** と判断（品質・一貫性・保守コスト）。  
**日記四コマの編集者ロジック + 参照画像ワークフロー** が差別化の核。

## 非機能要件（目標）

| 項目 | 目標 |
|------|------|
| 1四コマ（台本+5枚） | クラウド: 数十秒〜2分 / ローカルSD: 数分〜十数分 |
| キャラ一貫性 | 「同じパーカーの同じ人」と分かるレベル（100%は約束しない） |
| プライバシー | 日記はユーザー環境に留めたい → 将来ローカル台本オプション |
| 課金 | API原価を下回る単価は避ける（後述 ROADMAP） |
